# Select 1.0.0 — Self-hosted core release

Select 1.0.0 packages the current self-hosted AI-agent work management core. This release stabilizes the interfaces already available in the repository; **it is not a certification for regulated or production-critical deployment**.

## Included

- Agent teams, task assignment, projects, goals, role-based access and approval workflows.
- Deterministic delivery contracts, evidence receipts with contract hashes, and earned autonomy by task type.
- Strict human sign-off for financial/legal work and review-only code proposals.
- Repository-scoped review grants for code proposals: exact resource, expiry, revocation, and server-side enforcement.
- IMAP mailbox reading and SMTP sending, with content review and idempotency protections; scheduled routines.
- Costs, budgets, emergency stop, audit log, guided setup, and a no-key fictional demo company.
- Docker Compose deployment with FastAPI, PostgreSQL and Next.js.

## Important limitations

- **Real paid model provider flows have not been independently documented in this repository.** Users should run the documented live-provider probe and end-to-end checks with their own test account before connecting real company data.
- **No native Gmail OAuth or Microsoft 365/Graph OAuth integration.** Generic IMAP/SMTP and compatible app passwords are supported; providers that require OAuth cannot connect.
- **No sandboxed Claude Code/Codex runtime.** Code changes are *text-diff proposals for human review only*. Select does not run repository tests or apply/push patches.
- No independent 300-task comparative benchmark has been published; no claim of superior reliability is made.
- Real clean-machine macOS and Windows Docker installations have not been independently recorded in the repository.
- Security threat review, key rotation/restore, cross-version disaster recovery and retention controls require deployment-specific review. Review `SECURITY.md` and `docs/deployment.md`.
- Attachments are not parsed, no compliant electronic-invoice generation, and no single sign-on or 2FA.

## Installation

```bash
git clone https://github.com/Kirby54/Select.git
cd Select
./start.sh
```

Windows PowerShell: `./start.ps1`. Requirements: Docker Desktop or Docker Engine + Compose. Open `http://localhost:3000` and create the owner account.

**Upgrading an existing install:** Back up both the PostgreSQL database and encryption secrets/volume before pulling or restarting. Review `docs/deployment.md` and `CHANGELOG.md`. No production dataset migration or rollback guarantee is asserted by this release.

## Verification and provenance

The project uses Python verifier/API tests, frontend tests and typechecks, Playwright end-to-end flows, and a Docker Compose smoke test including PostgreSQL backup/restore on a disposable database. The GitHub release workflow must only publish if the full main-branch CI workflow passes for the exact released commit.

The maintainer reports having performed additional tests; their detailed independent evidence has **not** been provided here. The optional, stricter readiness checklist in `release/readiness.json` still tracks the work needed for independently certified production readiness.

For vulnerabilities, use private vulnerability reporting. This release is an explicit **core-scope 1.0 milestone**, not a statement that every future roadmap feature is complete.
